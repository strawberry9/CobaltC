# CobaltC on one page

Generated by `impl/tools/card.py` from the book, the tools' own help, the diagnostic registry and the
standard library's documentation; do not edit it here. Each part names where it comes from. The language
guide (`htmlguide/index.html`) and the book (`book/`) explain; this card is for looking things up while
writing.

Three habits save the most time: write every type (`i32 x = 1;`, `auto x = 1;`), call functions with their
type's name (`Vec::push(&mut v, x)`; there is no method-call syntax), and convert by name (`widen`,
`narrow`, `to_float`, `to_int`). `cobc --check FILE.cb` reports every independent error in one run;
`cobc --doc NAME` shows any item of the standard library.

### Declarations

```
import std;                                 // the standard library's names
import m::item;                             // one name, unqualified
module m { items }                          // a module; items are private unless exported
module m "path.cb";                         // the same, with a file's items as the body
export import m::sub;                       // pass on what sub exports as m's own

fn name(T1 a, T2 b) : R { body }            // a function; the last expression is the result
fn name(T1 a) { body }                      // returns nothing
fn name<T: bound>(T x) : T { body }         // generic; bounds: eq ordered number integer clone plain
fn Type::name(ref<Type, shared> self) : R   // associated: called as Type::name(&v)
fn Type::drop(ref<Type, exclusive> self)    // the destructor; the language calls it
fn f(ref<T, shared> a, ref<T, shared> b) : ref<T, shared> from a, b
                                            // a reference result: `from` names the
                                            // parameters it may come from
unsafe extern fn name(rawptr<u8> p) : i32;  // a C function
extern "./file.c";                          // C code to link

struct S { T1 a; export T2 b; }             // fields are private unless exported
resource struct S { ... }                   // a type with a destructor, moved not copied
enum E { A(T), B, C }                       // variants, with or without a payload
enum E : u8 { A = 1, B }                    // with numeric codes
bitstruct F : u8 { x : 1; pad : 7; }        // named bits of one integer
const T NAME = e;                           // a value known when the program is compiled
unittest "name" { ... }                     // a test; coby --unittest runs it
```

### Types

| Written | Meaning |
|---|---|

| `f32`, `f64`, `bool`, `str`, `void` | floats, truth, text constants, nothing |
| `ref<T, shared>`, `ref<T, exclusive>` | references, made with `&x` and `&mut x` |

| `Option<T>`, `Result<T, E>` | `Some(v)` / `None`; `Ok(v)` / `Err(e)` |

### Statements

```
T x = e;        auto x = e;        T x;           // declare; `auto` takes e's type
x = e;          x += e;                           // assign; also -= *= /= %= &= |= ^= <<= >>=
S { a, b } = e;                                   // take a struct apart into locals
if (c) { ... } else if (c2) { ... } else { ... }
if (Some(x) = e) { ... }                          // a pattern as a condition; also while
while (c) { ... }       for (init; c; step) { ... }
foreach (x in &c) { ... }                         // also &mut c, c (consumes), and lo..hi
foreach (i, x in &c) { ... }                      // with the position
break;    continue;    return e;    return;
match (e) { A(x) : e1, B : e2, _ : e3, }          // every arm ends with a comma
unsafe { ... }
drop(x);                                          // destroy early
_ = e;                                            // discard a value on purpose
```

| `*` `/` `%` | checked; division by zero faults |
| `+` `-` | checked |
| `<<` `>>` | the amount is a `u32` below the width |

| `||` | short-circuit |

## Coming from C or Rust

From `book/src/appendix-c-c-and-rust.md`.

The language guide has a full chapter for each. This appendix is the short
version: the habits to keep and the ones to drop.

### Coming from C

Keep: type-first declarations, `if`/`while`/`for` with parentheses and
braces, `printf` with its format strings, structs with designated
initialisers, `//` and `/* */` comments, and the feel of knowing where your
memory is.

Drop these habits, because the compiler will refuse them:

- **Implicit conversion.** `int` and `long` do not mix here, and neither do
  `i32` and `i64`. Every conversion is a named call: `widen`, `narrow`,
  `to_float`, `to_int`. There is no `int`; every integer names its width.
- **Wrapping arithmetic.** `a + b` that does not fit is a fault, not a wrap.
  Ask for wrapping by name when a hash function wants it.
- **Null.** There is no null pointer in safe code. A value that may be
  absent is an `Option<T>`, and the compiler makes you check it.
- **Pointers for everything.** A pointer that only lets a callee look is
  `ref<T, shared>`, one that lets it change is `ref<T, exclusive>`, and a
  pointer that hands over ownership is just passing the value. A
  `rawptr<T>` exists, inside `unsafe`, for the few places that need an
  address and nothing else.
- **`free`.** Nothing is freed by hand. A value that owns memory is a
  resource, and its owner's scope end frees it. There is no leak and no
  double free because there is no way to write either.
- **Error codes.** A function that can fail returns `Result<T, E>`, and the
  caller cannot forget to check it; a dropped `Result` is a compile error.
- **`switch`.** A `match` on an integer or text does the job, with a `_`
  arm, and a `match` on an enum must cover every variant.
- **Uninitialised variables.** A variable must be assigned on every path
  before it is read; the check is static.
- **`x & 1 == 0`.** In CobaltC this means `(x & 1) == 0`, as you meant.

What you gain is the compiler keeping the facts you used to keep in your
head. And `cobc --keep-c` shows you the C your program became, with every
check as an explicit line.

### Coming from Rust

Keep: ownership, moves, borrowing with two modes, enums with payloads,
`match`, `Option` and `Result` with `?`, generics with bounds, closures with
captures, `unsafe` as the marked boundary, threads whose data is moved or
lent, and the overall conviction that the compiler should prove things.

The differences are mostly about how far the checking is pushed to compile
time, and about spelling:

- **Borrow checking is static where it can be and dynamic where it cannot.**
  Rust rejects every program it cannot prove safe. CobaltC rejects every
  program whose text shows a conflict, and checks the rest while it runs,
  faulting at the first conflicting access. The accepted set is fixed by
  the language, not by the cleverness of the checker, and there are no
  lifetime annotations. A function returning a reference with one reference
  parameter borrows from it; with several, a `from` clause names the
  parameters the result may come from (`from a, b`), and a call borrows each
  of them while the result is used. A result whose parts come from different
  arguments cannot be described.
- **No traits.** There are six built-in bounds and no way to declare
  another. Generic code that needs an operation on your type takes it as a
  function parameter.
- **No method-call syntax.** `Vec::push(&mut v, x)`, never `v.push(x)`.
  The mode of every borrow is written where the borrow is taken.
- **No `mut` on bindings.** Every local can be assigned. What is controlled
  is who can reach a value, not whether it may change.
- **No iterators.** `foreach` walks the collections the language knows, and
  library functions such as `position`, `retain` and `sort_by` take
  function values. There is no iterator protocol to implement.
- **Three text types, spelled differently.** `str` is a copyable text
  constant, not a borrowed slice; `String` is owned text; `StringView` is
  Rust's `&str`, a borrowed view of a `String`.
- **Declarations are type-first.** `i32 x = 5;` and `auto y = x;`. Blocks,
  `if` and `match` are expressions, as in Rust, but conditions take
  parentheses and `match` arms are `pattern : expression,`.
- **Overflow always checks.** In Rust it depends on the build profile. Here
  it is a fault in every build, and the wrapping and checked families are
  the only way to get another behaviour.
- **A closure's capture list is written and checked.** `[a, b](i32 x) { ... }`
  must name exactly the outer variables the body uses; how each is captured
  is decided by the body, and `move` captures by value.
- **A fault in a thread is contained.** It ends that thread, poisons its
  mutexes, and arrives at `try_join` as a value; a plain `join` re-raises
  it. Much like a panic, with the policy fixed by the language rather than
  the library.
- **Interior mutability is a mutex or an atomic, and nothing else.** There
  is no `Cell` or `RefCell`; `Rc<T>` gives shared read access and a mutex
  inside it gives mutation.

Rust programmers tend to find CobaltC easy to read and briefly annoying to
write, until the qualified calls and the written borrows become
automatic. The guide's Rust chapter goes through each of these at length,
with the reasons.

### When a habit slips through

The compiler answers most habits from either language with the CobaltC form
in its message: `v.len()` with `Vec::len(x, ...)`, `let x = 1;` with
`i32 x = 1;` or `auto x = 1;`, `x as u64` with `widen<T>(x)`, `i++` with
`i += 1`, `println!` with `printf`, `NULL` with `Option<T>`. `CARD.md`, at the
top of the repository, lists a hundred such habits with their messages.

```
Compile a CobaltC program to a native executable.

Checks FILE.cb with the same front end as `coby`, lowers it to C, and
compiles that C with `cc` (or the compiler --cc names) against the
`cbrt` runtime library found beside this executable.

Options:
  -o OUT       Write the executable to OUT. Default: FILE.cb without its
               extension (`foo.cb` -> `foo`). A program whose modules sit
               in a directory of that name (`foo/`) needs -o.
  --run        Compile to a temporary directory, run the program, forward
               its exit status and output, then delete the directory. With
               `-o`, the executable is written to OUT instead and kept.
               Every ARG after FILE.cb is passed to the program (its
               argument 0 is the first), so options go before FILE.cb.
  --explore N  Compile, then run the program N times, each under another
               order of its threads chosen by a seed (1 to N), and group
               the runs by outcome: exit status, output and errors. One
               thread runs at a time; the turn passes at a `spawn`, a
               wait, a mutex released, a thread's end, a call outside the
               program (a socket, input, sleeping) and now and then
               between two of the program's checks. Each outcome is shown
               with a seed that gives it; the exit status is 1 when the
               runs differ. Implies --run; ARGs and standard input (read
               once, unless a terminal) go to every run.
  --schedule-seed S
               Run once (implies --run) under the order seed S gives, as
               `--explore` ran it: the same seed, the same order, so a
               run that ended differently can be replayed. Setting
               COBALTC_SCHEDULE_SEED=S in a compiled program's
               environment does the same.
  --lib        Build a library (D-0257): the program's `extern fn` definitions
               as a static archive (default libNAME.a beside the source), the
               runtime libcbrt.a copied beside it, and NAME.h with the C
               prototypes, the structs that cross by value, and the link line.
               A library has no `main`; nothing runs.
  --keep-c     Keep the generated C file instead of deleting it after
               `cc`. It sits beside the executable with the extension
               replaced by `.c` (`-o prog` -> `prog.c`, `a.out` -> `a.c`).
               Under `--run` without `-o` it lives in the temporary
               directory and is deleted with it. When `cc` fails the C is
               always kept and its path printed.
  --no-line-directives
               Leave the `#line` directives out of the generated C. By
               default each line of C made from one of the program's own
               statements is preceded by `#line N "FILE.cb"`, so the C
               compiler's messages, a debugger and a sanitizer name the
               program's file and line rather than the C's; code made for
               `std` keeps the C's own lines.
  -g           Compile the generated C with debug information (`cc -g`)
               and keep it in the executable. With `-O0 -g` a debugger
               such as gdb steps through the program's `.cb` lines, and a
               sanitizer's report (`--cc` naming a compiler wrapper that
               adds `-fsanitize=address`) names them.
  --report-tracking
               Compile nothing: list the lines of the program's own files
               whose generated C still calls the runtime's tracking (paths,
               objects, checked accesses), those inside loops first, with
               the kinds of call on each. Bounds and overflow checks are
               not listed. Chapter P of the guide says what each form
               costs and how to write code the compiler can see through.
  --report-guards
               Compile nothing: for each loop of the program's own files
               that indexes a slice, the length guard (D-0320) the
               compiler puts before it, as `slice_len(s) >= N` tests, or
               why an index has none (a name in it is not kept below a
               value known before the run), and whether the guard is used.
               It says what cobc writes; whether the C compiler then drops
               the checks inside the guard is for `objdump` or `perf
               annotate` on the executable to show.
  --certificate FILE
               Write to FILE what the static pass decided before the run
               (D-0299): for each function body, `decided` (no conflict of
               its frame-held references left to the run, so no record of
               them is kept) or `left` with each conflict the run checks,
               the point checks, and the program's verdict (`decided`, or
               why paths were kept). With --check, the static pass's part
               alone, for one program. `cobmodel certify FILE PROG.cb`
               checks a fragment program's certificate against every
               interleaving of its threads.
  --all-checks
               Use no proof about a function's reference parameters: every
               access through one is checked where it is made (D-0209). For
               comparing against the elided forms; slower.
  --bootstrap-form
               Emit the general checked form only: --all-checks, no
               elisions (D-0274). The reference for the code
               generator written in CobaltC; much slower.
               COBALTC_BOOTSTRAP_UPTO=N switches off D-0274's stages 1..N
               only (0 the default form, 10 this one; CHG-0368).
  --allow-deprecated
               Accept a use of a name marked `[[deprecated(...)]]` (D-0303):
               each use is a warning on standard error, with the message, in
               place of the error `diag.deprecated-use`. A removed name
               (`[[removed(...)]]`) stays an error.
  --warn-shadow
               Note, on standard error, each item of the program whose name
               hides an imported one (a `struct Vec` beside `import std;`):
               the program's own item is the one used (`spec/17`), and this
               is the only place that says so. Exit status unchanged.
  -v, --verbose
               Print each command cobc runs, on standard error, before it
               runs it: the C compiler on the generated C, `cc -c` on each
               C file named by `extern "…";`, and with --run the program.
               Each is a line beginning `+ `, quoted so that it can be
               pasted into a shell. Also where the generated C is written,
               and whether it is kept or removed.
  -s, --strip  Leave the symbol table out of the executable too (the
               linker's --strip-all),
               for the smallest file: a hello world is about 0.6 MB
               instead of 0.8 MB. The program runs the same -- its fault
               messages come from the locations compiled into it, not
               from symbols -- but a profiler or debugger can no longer
               name its functions.
  -O LEVEL     Optimization level passed to `cc`: 0, 1, 2, 3, s, or g.
               Also accepted joined: -O0, -O2, -Os, ... Default: 2.
               Given more than once, the last one wins.
  -march=CPU   Target CPU passed to `cc`, e.g. `native`, `x86-64-v3`,
               `haswell`. Default: `cc`'s own (baseline x86-64), which runs
               on any x86-64 machine; `native` may not run on an older CPU
               than the one that compiled it. Given more than once, the
               last one wins.
  --cc COMPILER
               The C compiler to use instead of `cc`: a name found on
               PATH, such as `gcc` or `clang`, or a path. Also accepted
               as --cc=COMPILER. It is given the same options as `cc`,
               which GCC and Clang both accept. Which is faster depends
               on the program (bench/RESULTS.md). Given more than once,
               the last one wins.
  --target TRIPLE
               The platform to compile for (D-0255): x86_64-unknown-linux-gnu
               or x86_64-pc-windows-gnu. Default: the one cobc runs on. For
               Windows from Linux the C compiler is MinGW-w64's
               (`x86_64-w64-mingw32-gcc`, or --cc), the runtime is the one in
               target/x86_64-pc-windows-gnu/release (built with Rust 1.77.2),
               and the executable is FILE.exe. --run and --explore run it with
               the program named by COBALTC_RUNNER, such as `wine64`.
  --check PATH...
               Check each program statically and build nothing: each FILE.cb
               named, and each `.cb` file in each directory named (hidden
               directories and `target/` skipped). It must be the first
               argument; no other option goes with it. A rejected program
               prints the diagnostic a build would print, and a file named
               by `extern "./…";` that is missing is reported, but no C is
               written or compiled. In a directory, a file another program
               there loads as a module (`module m "./m.cb";`) is checked
               as part of that program, not on its own. Nothing is printed
               for an accepted program. `coby --check` does the same
               without the `extern` files.
  --emit-c [--c-name NAME] [-o OUT] FILE
               The program's C, nothing compiled or linked: the file
               `--keep-c` keeps, written to OUT, or on standard output
               without -o or with `-o -`. NAME is the name its `#line`
               directives give it (default OUT, else a.c). A program the
               static pass rejects gets its diagnostic and status 1, and
               OUT is not written.
  --doc [NAME] An item of the standard library (`Vec::push`, `printf`), a
               type and its functions (`Vec`), or a module (`std::text`),
               from the documentation in std's own source; with no NAME,
               the modules. Exit 1 when nothing has that name (the
               nearest that does is named). `coby --doc` is the same.
  --check-syntax [--origin PATH] (FILE | -)
               Whether one text parses, and nothing else: FILE, or standard
               input for `-`, its `module m "./m.cb";` files found
               relative to PATH (FILE by default). Exit 0 it parses, 1 it
               does not (the error, `PLACE: MESSAGE (column C)`, on
               standard error), 2 it cannot be read. A program the parser
               builds but the static pass would reject parses. For the
               formatter written in CobaltC (impl/selfhost/cobfmt), which
               refuses what this refuses; `coby --check-syntax` is the same.
  --unittest   Build the program's tests instead of the program (D-0230):
               each `unittest` block in its files, run in order by a
               `main` of their own, each in a thread of its own, its
               fault reported and the next one run; the program's own
               `main` is checked but not run, and a file of tests needs
               none. The executable prints `test FILE:LINE NAME ... ok`
               (or `FAILED` and the fault) for each and a summary, and
               exits 1 when one failed. With --run, run them now: `cobc
               --unittest --run lib.cb`; with -o, keep the test program.
  --unittest-filter TEXT
               With --unittest: only the tests whose name contains TEXT
               (an unnamed test matches none); a filter that matches no
               test is an error.
  --unittest-std
               Run `std`'s own tests, the examples of the std reference,
               in place of the program's (implies --unittest).
  --explain    Show each diagnostic with its full entry from the
               specification's registry: the rule, the invariant, what was
               required and observed, the provenance and the examples, after
               the short form (the message, the location with the source line
               and a caret, and the repair). A compiled program shows its
               faults that way when COBALTC_EXPLAIN=1 is set in its
               environment, which --explain sets for --run.
  --about      What cobc is, next to the interpreter coby, and exit.
  -h, --help   Print this help and exit.

The program's own C code: `extern "./shapes.c";` (or a `.o`, `.a` or
`.so` file) links a file, its path relative to the file that declares
it; `extern "z";` links an installed library, as `cc -lz`. A `.c` file
is compiled on its own with the C compiler's warnings shown; a `.so` is
found from any working directory. Each is linked once, and a missing
one is reported at its declaration.

The executable: on Linux the linker is given `-Wl,--gc-sections` and
`-Wl,--strip-debug`, so it holds only the parts of the runtime the
program uses and no debug information (the generated C is compiled
without `-g` unless -g is given, which also keeps it); its symbol table
stays, for profilers and debuggers, unless -s removes it.

Floating point: the C compiler is always given `-ffp-contract=off`, so every float
operation is rounded on its own as the specification requires (spec/06),
even where -march enables fused multiply-add instructions; and
`-fno-optimize-sibling-calls`, so a tail call is still a call and a
recursion too deep for the stack faults (diag.stack-exhausted) whatever
the C compiler and optimization level.

Exit status:
  0    compiled (with --run: the program's own exit status, which is
       main's value for `fn main() : u8`; with --check: every program
       accepted)
  1    the program (with --check: one of them) was rejected statically;
       the diagnostic is on stderr
  2    usage error, unreadable file, C compiler failure, or C code
       named by `extern "…";` that is missing or does not compile
  3    unsupported: a construct the compiler cannot compile yet, or an
       `extern fn` naming a function not in libc, libm or the
       program's C code
  4    internal error: a bug in cobc, reported as one line (with Rust's
       backtrace when RUST_BACKTRACE is set); please report it with
       the program
```

| `diag.spawn-borrow-closure` | a spawned thread needs a `move` closure | static | add `move` |
| `diag.mutex-reentrant-lock` | this thread already holds the lock | dynamic | release the guard first |
| `diag.trusted-outside-unsafe` | this needs an `unsafe` block | static | wrap in `unsafe` after verifying the asserted property. Related: `ex.unsafe-required` |
| `diag.extern-non-ffi-type` | this type cannot cross into C | static | pass `rawptr`/scalars, or a struct without resources, enums or bitstructs |
| `diag.null-pointer` | C's `NULL` where text was expected | dynamic | test with `is_null` first; C functions return `NULL` for "none" |
| `diag.assert-failed` | assertion failed | dynamic | the program's own condition names what was assumed; find why it did not hold |
| `diag.channel-zero-capacity` | a channel needs a capacity of at least 1 | dynamic | give the number of values the channel may hold; 1 for a hand-over |
| `diag.barrier-zero-parties` | a barrier needs at least one party | dynamic | give the number of threads that meet at the barrier |
| `diag.channel-deadlock` | the only running thread waits on a channel nothing else can change | dynamic | send or receive from another thread, or `close` the channel before receiving the last value |
| `diag.thread-cancelled` | this thread was cancelled | dynamic | none is needed when the stop was meant: the thread's failure is contained, and its joiner or handle sees it; to let a thread finish, do not cancel it |
| `diag.mutex-poisoned` | a thread failed while holding this lock | dynamic | find that fault (`try_join` gives it); keep a lock's block short, so that little can fail inside it |
| `diag.deadlock` | these threads would wait for each other forever | dynamic | take locks in one order; send before waiting to receive; store and notify before waiting on an atomic another thread waits to see change; join a thread only after giving it what it waits for |
| `diag.result-discarded` | a `Result` is discarded | static | handle the error (`?`, `match`), or discard the value on purpose with `_ = e;` |
| `diag.stack-exhausted` | calls nested too deeply for the stack | dynamic | recurse less deeply (a loop, an explicit stack in a `Vec`) |
| `diag.unwrap-failed` | nothing to unwrap: `None` or `Err` | dynamic | match on the value, or give a default with `unwrap_or`, where its absence is possible |
| `diag.alloc-failure` | memory could not be allocated | dynamic | none at the language level; callers needing recovery call `allocate` themselves |
