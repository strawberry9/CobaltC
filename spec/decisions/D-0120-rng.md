# D-0120 — A reproducible pseudo-random generator in `std`

Status: ACCEPTED (2026-09-30, the owner: "proceed with F10 as D-0120" — the findings report's F10)
Kind: Decision (`spec/02-schema.md`)
Governed by: `CobaltC_Master_Instructions.md` §1, §8 (item 10), §9 ("Library helpers")
Depends on: rule.arith.alt (`wrapping_*`), rule.arith.bitwise, rule.arith.convert (`to_float`), D-0061 (clocks, for a program that wants a fresh seed)
Affects: `spec/21` §0 and §2g (3.48.0), `spec/conformance.md`, the guide §21, `impl/src/prelude.rs`

## Problem

Twelve programs of the corpus declare their own generator — an LCG
or a xorshift with `next` and `below(n)` — every one deterministic on
purpose, so that its output is reproducible under `coby` and `cobc`
alike, and every one with its own quality and its own (usually biased)
`below`. A reader must check both each time.

## Candidate mechanisms

1. **Leave it to programs.** Twelve copies and counting.
2. **A generator in `std` whose algorithm the specification fixes**,
   so that the same seed gives the same sequence in every
   implementation. Selected: "a reproducible random number below `n`"
   is one intent (§9's test), and reproducibility is what the programs
   already want. An unspecified "good generator" would let the two
   tools disagree, which the conformance claim forbids.
3. **A generator seeded from the clock by default.** Loses
   reproducibility by default; a program seeds from `monotonic_ns()`
   itself when it wants that.

## Selected design

    Rng::seed(u64 s) : Rng
    Rng::next_u64(ref<Rng, exclusive> r) : u64
    Rng::below(ref<Rng, exclusive> r, u64 n) : u64        -- unbiased; n = 0 is diag.div-by-zero
    Rng::unit_f64(ref<Rng, exclusive> r) : f64            -- [0, 1), from 53 bits

xoshiro256** for the stream, seeded through splitmix64 (both public
domain, four `u64` words of state, shifts, rotates, xors and one
multiply each); `below` by rejection of the top partial block; all
written in CobaltC and, step by step with check values, in `spec/21`
`[Rng]`, as `[CRC32]` is. The sequence is normative. It is a
general-purpose generator and not suitable for cryptographic purposes
(keys, tokens, nonces): the specification and the guide both say so
(the owner's instruction, 2026-09-30).

## Compatibility impact

Additive; a program's own `Rng` shadows `std`'s (D-0024).

## Revisit conditions

A different distribution (normal, exponential) or a jump function for
parallel streams, as its own decision if programs need it.
