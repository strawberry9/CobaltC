# D-0212 — The edition manifest and the evidence tiers

Status: ACCEPTED (2026-10-11; the owner: "continue actioning the outstanding items in the Action plan" — WI-10)
Kind: Decision (`spec/02-schema.md`)
Governed by: `CobaltC_Master_Instructions.md` §13, §20
Depends on: D-0207, D-0211
Affects: `spec/MANIFEST.md` (new, generated), `spec/README.md`, `spec/02` 1.0.74 (CHG-0250); `impl/tools/manifest.py`
(new), `impl/battery.sh` (`SUMMARY`); the push procedure

## Problem

The review (F-10, §5.2; `ChatGPT_review/ACTION-PLAN-2026-10-11.md` WI-10) observed that a green battery is a
record of one run on one machine, not a certificate, and that nothing says which bytes an edition consists
of: the repository is kept as a single commit that every update replaces, so a commit hash names nothing
durable, and the edition rows say "rapid, no battery" or nothing about what was run.

## Decision

1. **`spec/MANIFEST.md`**, generated by `impl/tools/manifest.py` (Python 3, standard library only, runs on
   Windows): the edition; the SHA-256 of every file under `spec/` (itself excepted) with each artifact's
   `Version`; the highest D and CHG numbers; the conformance cases (count, a hash of the sorted listing, a
   hash of their contents); the last battery's run, result, scope, toolchain (`rustc -V`, `gcc`, `clang`,
   kernel) and tree fingerprint; and the evidence tier. It carries no date of its own, so a second run on an
   unchanged tree rewrites nothing (`--check` says whether it is current).
2. **The tree fingerprint**: the SHA-256 over every file git tracks or would track (not ignored), the
   manifest itself excepted, as sorted `path`, `sha256` pairs. `impl/battery.sh` writes it, with the run's
   result and toolchain, into `SUMMARY` beside `REPORT.md`; the manifest claims the tier `battery` only when
   the newest green `SUMMARY` carries the current fingerprint, whatever the writer asked for.
3. **Evidence tiers** (`spec/README.md`): *reviewed*, *tested*, *battery*, *explored to N*, one word per
   edition row from this edition on, and in the manifest. "Rapid, no battery" in the existing rows is
   *reviewed*.
4. **The push procedure**: after the edition bump and before the squash, `impl/tools/manifest.py --tier
   <tier> [--explored N]`; the manifest ships with the edition it describes.

## Results

`impl/tools/manifest.py` on this tree: 0.6 s; run twice, the second run reports "unchanged". The manifest
for this edition (D-0208 to D-0212) claims *tested and explored to 40*: both conformance suites and the
compiled suite under `--all-checks` green, the six D-0210 cases under `cobc --explore 40`; no full battery
was run for it (the owner authorises batteries).

## Amendment (2026-10-11, CHG-0256)

The second independent review (F-08) noted that the manifest of edition 2026.101101 claimed *tested and explored
to 40* while naming no run: "the last battery" was empty, and a *tested* claim had no record format at all. Two
changes (`ChatGPT_review/ACTION-PLAN-2026-10-11b.md` WI-7, Q5):

1. `impl/tools/suites.sh` runs the targets the *tested* tier means — `coby`'s file suite, spec rows, embedded
   cases and coverage check; `cobc`'s compiled spec rows and compiled suite, the suite again under
   `--all-checks` with GCC, and its other targets — each to its own log, then, given `EXPLORE` and
   `EXPLORE_CASES`, `cobc --explore N` over those cases, and writes a `TESTED` record: the run, its result, the
   fingerprint, the toolchain, each target's `test result` lines, and the bound when every explored case gave
   one outcome. `manifest.py` prints "The last suite run" from the newest passing record for this tree, takes
   the exploration bound from it, and writes "tested (no record for this tree)" when there is none.
2. The fingerprint leaves out the top-level `README.md`, whose "Commit Update" line the push procedure writes
   after any run and which no test reads; without that, no run could ever match the pushed tree. `spec/README.md`
   says that a change to `MANIFEST.md` alone (a record added after publication) keeps the edition.
