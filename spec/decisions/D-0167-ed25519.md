# D-0167 — Ed25519 in `std::crypto`

Status: ACCEPTED (2026-10-05, the owner: "Make std::crypto feature complete")
Kind: Decision (`spec/02-schema.md`)
Governed by: `CobaltC_Master_Instructions.md` §1
Depends on: D-0154 (X25519's field arithmetic), D-0156 (SHA-512), D-0159 (the Montgomery arithmetic modulo a group order)
Affects: `spec/21` §0, §2m (4.32.0), `spec/registry/diagnostics.md` (1.48.0), `spec/conformance.md`, the guide §21, `impl/std/crypto.cb`; `CHG-0195`

## Problem

Ed25519 (RFC 8032) is the signature most new protocols choose: SSH keys,
TLS 1.3 certificates, signed software, tokens. `std` verified only RSA and
ECDSA, and signed with nothing. The flagship road (D-0151) listed Ed25519
among the pieces to add after the TLS client.

## Candidate mechanisms

1. **Pure Ed25519: `ed25519_private_key`, `ed25519_public_key`,
   `ed25519_sign`, `ed25519_verify`, on the X25519 field arithmetic and on
   the Montgomery arithmetic the NIST curves use, modulo L.** Selected.
2. **Ed25519ph and Ed25519ctx as well.** Neither TLS, X.509 nor SSH uses
   them. Not adopted; a later decision if a format needs one.
3. **Ed448 as well.** Rare in practice, a second field and hash. Not
   adopted.

## Selected design

**`spec/21` §2m:**

- `ed25519_private_key() : array<u8, 32>`: 32 bytes of `os_random_bytes`.
- `ed25519_public_key(private_key) : array<u8, 32>`: the clamped scalar
  of SHA-512(private key) times the base point, encoded.
- `ed25519_sign(private_key, message) : array<u8, 64>`: R ‖ S of
  RFC 8032 §5.1.6, deterministic: the same key and message give the same
  signature, and no random number can repeat.
- `ed25519_verify(public_key, message, signature) : bool`: [S]B = R + [k]A
  (§5.1.7), with S below L and R and A canonical encodings of points; a
  key or signature of another length is false.
- A private key that is not 32 bytes is `diag.crypto-length`.

Points are kept in extended coordinates with the complete addition
formula; the scalar multiplication doubles and adds at every one of 256
bits and keeps the sum by a mask, so `[Constant-Time]` covers signing and
key generation. Verification uses only public values and the same code.

## Compatibility impact

Additive.

## Revisit conditions

- A format needing Ed25519ph or Ed25519ctx.
- Verification throughput, if a program verifies many signatures: a
  variable-time double-scalar multiplication would be faster.
